Spazio sul disco

Significato delle misure

Calcolo: si legge la capacità del disco che ospita il database, lo spazio disponibile e la dimensione dei file del database, compresi i file temporanei di scrittura. Nel database si contano le pagine occupate e quelle interamente disponibili per nuovi dati.

Cosa rappresenta: la barra indica la quota di disco occupata o riservata, condivisa da PopX e dagli altri programmi. Il dettaglio del database mostra quanto spazio è allocato e quanto può essere riutilizzato.

Come leggerlo: una barra vicina al 100% indica poco spazio disponibile. Dopo la rimozione di una run, lo spazio interno riutilizzabile può crescere mentre la dimensione del file resta stabile. Le nuove scritture possono usare quelle pagine; una compattazione separata può restituirle al disco.

WSL: il filesystem Linux risiede in un disco virtuale che può crescere sul disco Windows. Lo spazio libero del filesystem virtuale va confrontato separatamente con quello reale di Windows; qui il secondo valore non è disponibile.

Arresto automatico per dimensione del database

Il parametro database_limit_gb, disponibile nella Configurazione della dashboard e nell’INI, vale 10 GB decimali per impostazione predefinita. I cambiamenti si applicano al prossimo Start/Restart.

La dashboard controlla ogni mezzo secondo la somma dei file SQLite, WAL e SHM di tutte le run. Al raggiungimento della soglia salva e verifica un checkpoint, carica una nuova run in pausa, elimina tutti gli storici precedenti recuperando lo spazio del file, quindi riprende. Se il salvataggio o il caricamento falliscono, conserva lo storico e segnala l’errore. Start, Restart e Resume dalla dashboard vengono bloccati se i file sono già oltre il limite.

La soglia avvia la rotazione: i dati già in coda e il riepilogo finale possono superarla leggermente. Snapshot esterni, altri database e altri file WSL hanno occupazioni separate. Il controllo opera finché il backend della dashboard è attivo; eventuali errori di misura sono mostrati nel misuratore.

Rimuovi una simulazione precedente

Scegli una run conclusa. La rimozione elimina campioni, eventi, genomi registrati, ambiente, risultati diagnostici e snapshot salvati riconosciuti come appartenenti alla run. La run collegata al simulatore è protetta. La conferma riguarda esclusivamente la run selezionata.

La rimozione procede a blocchi. Lo spazio liberato nel database viene riutilizzato dalle nuove scritture. Gli snapshot con percorsi non riconosciuti vengono conservati e segnalati. I registri tecnici di deduplicazione dei messaggi restano disponibili.
